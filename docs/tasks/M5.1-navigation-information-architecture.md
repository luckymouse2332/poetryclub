# M5.1 站内通知交互与导航入口拆分

## 背景

当前通知入口与账户菜单的职责混合，桌面和移动端都出现过高的浮层与不清晰的信息层级。本任务只重构站内通知相关 UI/UX，并保持回中诗社现有 Header、首页和服务端通知行为。

## 范围

- [x] 将桌面“通知”与“我的”拆成两个独立入口，通知使用 Popover 快速预览。
- [x] 移动端“通知”直达 `/notifications`，“我的”只保留账户操作。
- [x] 抽象可由 Popover 与完整通知页复用的 `NotificationListItem`。
- [x] 完善通知列表的 unread、read、empty、loading、error 和窄屏状态。
- [x] 更新相对时间、键盘交互、SSE 同步和响应式 E2E 验收。

## 非目标

- [x] 不改变认证、授权、登出 Server Action 或通知服务端数据契约。
- [x] 不新增本次导航改造以外的数据库表、migration、环境变量、头像、搜索或未实现的导航功能。
- [x] 不切换分支、创建发布标签或推送远程。

## 架构边界

- `SiteHeader` 保持纯 UI 边界；认证数据继续由 `AuthNavigation` 在服务端读取。
- 客户端菜单只接收可序列化的权限布尔值、通知数量和通知视图数据，不读取数据库或会话对象。
- 下拉菜单使用现有 shadcn/ui `DropdownMenu`，保持 Radix 交互、键盘焦点和设计 Token 约定。
- 现有通知入口的已读操作、SSE 刷新和路由保护保持不变；只调整客户端展示层和触发位置。

## 验收条件

- [x] 匿名用户只看到公开入口和“登录”。
- [x] 登录用户桌面端看到独立“通知” Popover 和“我的”账户菜单；移动端通知直达通知中心。
- [x] 正常管理员额外看到独立的“管理”，其他用户看不到。
- [x] 320、375、390、430、768、920、1024、1440px 均无水平溢出，管理员移动导航明确排列。
- [x] Popover 支持焦点、Escape、外部点击和键盘操作，通知行为与 M5.0 保持一致。
- [x] 移动端“管理”和“我的”复用同一套文字二级导航；账户二级导航仅包含“我的诗作”和“账户”，桌面“我的” Dropdown 保持不变。

## 发布影响

- 预期版本影响：`无需单独发布`
- migration / 环境变量 / 部署顺序：无。
- 兼容性与回滚边界：仅回滚导航组件、测试和文档改动；保留 M5.0 通知数据与服务。

## 测试

- 更新 `tests/e2e/home.spec.ts`、`tests/e2e/auth-flow.spec.ts` 和通知相关 E2E。
- 验证 `pnpm check:conventions`、`pnpm typecheck`、`pnpm lint`、`pnpm test`、相关 Playwright E2E 和 `pnpm build`。

## 风险 / 回滚

- Popover 内容变长可能在窄屏接近视口边界；使用 Radix 可用高度限制和内部列表滚动，并通过 Playwright 检查。
- SSE 刷新必须同时更新未读徽标和 Popover 最近列表；若交互回归，只回滚展示层，不回滚通知服务端代码。
- 本地和生产 E2E 都要求 `REDIS_URL` 指向可用 Redis；通知流不再使用同进程回退，Redis 暂时不可用时由 SSE 断线重连，并由通知中心从 PostgreSQL 恢复历史状态。生产构建仍受 `.env.local` 缺少 `RESEND_API_KEY`、`EMAIL_FROM_ADDRESS` 阻断，补齐现有环境变量后可继续运行。
