# M3.0 回归修复：管理员治理 E2E hydration 竞态

## 背景

管理员治理 Playwright 用例“members receive 403 and cannot invoke a captured administrator action”超时。测试在管理页面的服务端 HTML 已加载、但管理操作 Client Component 尚未完成 hydration 时替换会话并点击“隐藏”，导致点击没有触发 React/Radix 对话框。

## 范围

- [x] 在捕获管理员操作后、替换会话前确定性等待目标控件完成 hydration。
- [x] 使用 Playwright web-first 断言等待确认对话框可见。
- [x] 验证普通成员仍收到 403，且失败操作不改变诗作、不写入审计日志。

## 非目标

- [x] 不修改管理员鉴权、治理 Server Action 或生产 UI 行为。
- [x] 不使用固定延时掩盖 hydration 竞态。

## 架构边界

仅修改 E2E 测试及任务文档。Server Action 仍作为不可信服务端入口独立执行身份认证、管理员授权、输入及业务规则校验；测试不得通过绕过浏览器行为直接替代关键安全断言。

## 验收条件

- [x] 失败用例可稳定打开确认对话框并观察服务端权限错误。
- [x] focused Playwright 用例通过。
- [x] typecheck、lint、unit tests 及完整 E2E 通过。

## 风险 / 回滚

风险仅限测试等待条件与会话恢复逻辑；若等待条件与 React 升级不兼容，可回滚本测试改动并改用应用暴露的稳定 hydration 标记。不得以增加全局 timeout 或固定 sleep 作为回滚方案。
