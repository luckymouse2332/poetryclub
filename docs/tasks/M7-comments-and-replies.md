# M7 作品评论与一级回复

## 背景

诗作发布、访问控制、站内通知与管理员治理已经形成稳定闭环，但读者仍无法围绕作品留下可持续的公开讨论。本任务为 `v1.5.0` 增加评论和一级回复，在首版限制交互深度的同时保留未来扩展任意层级的领域结构。

## 范围

- [x] 新增评论 Schema、`0006` migration、索引、约束和管理员审计枚举。
- [x] 实现正文校验、访问控制、幂等创建、十秒发布冷却、编辑、软删除、隐藏、恢复、活动时间重算和评论计数。
- [x] 实现根线程与回复的版本化游标读取、最小安全 DTO、通知收件人去重和实时提示。
- [x] 在诗作详情、完整线程、公开诗作列表和管理员工作区接入评论功能。
- [x] 更新产品、架构、设计系统、About、条款、隐私说明、任务清单和 CHANGELOG。
- [x] 补齐单元、集成、Route Handler 与 E2E 覆盖，并完成全部质量命令。

## 非目标

- [x] 不实现点赞、收藏、分享、匿名评论或评论个人主页。
- [x] 不开放任意层级回复界面，服务层只接受根评论与一级回复。
- [x] 不保存修订历史，不支持附件、Markdown 或未经净化的 HTML。
- [x] 不在功能分支修改版本号、创建发布标签或执行破坏性数据回滚。

## 架构边界

页面和 Route Handler 保持薄层，评论领域规则集中在 `src/server/services` 与 `src/server/validation`，交互组件和 Server Actions 位于 `src/features/comments`。数据库访问只发生在服务端模块。所有写入口独立验证身份、对象权限、输入、诗作状态和状态转换；所有读取入口重新解析会话并验证作品访问权。客户端只接收渲染所需 DTO，正文以纯文本显示，列表全部分页。

## 验收条件

- [x] 游客可以读取公开作品评论，成员作品评论仅对有权读取作品的正常成员开放。
- [x] active 成员和管理员可以创建根评论和一级回复，suspended 账号及更深回复均被拒绝。
- [x] 作者可以编辑和软删除自己的可操作评论，结构占位、回复和线程排序保持正确。
- [x] 管理员隐藏与恢复会在同一 PostgreSQL 事务中写入治理状态、审计和通知。
- [x] 评论计数、通知定位、根线程和更早回复游标加载符合产品规则，响应无敏感字段并设置 `private, no-store`。
- [x] 390、1024、1440px 下交互可访问且无水平溢出，用户文本不会作为 HTML 执行。
- [x] 约定检查、类型检查、Lint、单元、集成、数据库检查、相关及全量 E2E、生产构建和空库 migration 验证通过。

## 发布影响

- 预期版本影响：`MINOR`，目标版本为 `v1.5.0`。
- migration / 环境变量 / 部署顺序：提交 `0006` migration；沿用现有 `REDIS_URL`，migration 可先于应用部署。
- 兼容性与回滚边界：应用可回滚到 `v1.4.0`，保留新增表和评论数据，不执行破坏性降级。

## 测试

单元测试覆盖正文、ID、游标、深度、治理原因、错误映射和 DTO。集成测试覆盖幂等、权限、状态转换、事务、活动排序、计数、通知与 Redis 限流。Route Handler 测试覆盖匿名读取、成员访问、游标、线程归属、安全字段与缓存头。E2E 覆盖读写、治理、通知定位、游标加载、计数、键盘与响应式布局。

## 风险 / 回滚

主要风险是自引用结构写入错误、并发回复造成活动时间或计数失真、成员作品信息通过通知泄露、Redis 故障影响发布，以及治理后线程窗口失效。通过数据库约束、事务内重算、最小通知 payload、限流故障放行和严格游标校验控制。回滚应用时保留 `0006` 数据结构，后续版本可以继续读取并恢复功能。
