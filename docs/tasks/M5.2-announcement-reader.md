# M5.2 系统公告阅读页

## 背景

M5.0 和 M5.1 已提供通知中心、最近通知预览、未读状态和系统公告发布能力。当前通知列表只显示摘要，公告正文最多允许 4000 个字符，普通收件人没有完整阅读已发布公告的入口。

## 范围

- [x] 增加成员端系统公告详情页 `/announcements/[id]`。
- [x] 按发布时生成的 `notification_recipient` 收件人快照授权公告读取，并在进入详情页时标记已读。
- [x] 将系统公告通知统一指向公告详情页，保留公告原有站内链接作为详情页中的后续操作。
- [x] 补充服务端、页面和通知入口的测试。

## 非目标

- [ ] 不为治理结果、评论、回复、点赞或收藏通知增加通用详情页。
- [ ] 不改变公告发布、不可编辑、不可撤回、不可删除和受众快照规则。
- [ ] 不新增数据库表、migration、外部推送或后台服务。

## 架构边界

- 路由页面位于 `src/app/announcements/[id]`，公告读取与授权位于 `src/server/services/notifications`。
- 页面只通过服务端模块读取数据库；不得把数据库访问放入客户端组件。
- 详情页必须先认证，再按 `notification_recipient` 与公告对应的 `notificationId` 做对象级授权；不得根据当前账号状态重新计算历史受众。
- 公告标题、正文和链接均按现有纯文本与站内相对路径规则展示。
- 进入详情页标记已读必须与收件人授权在同一服务端事务边界内完成，并保持幂等。

## 验收条件

- [x] 已登录且在公告收件人快照中的用户可以访问已发布公告详情页并看到完整正文、发布时间和可选站内链接。
- [x] 匿名用户、非收件人和不存在的公告不能读取公告内容。
- [x] 进入详情页后该用户对应的通知变为已读，未读数量和通知列表会同步更新。
- [x] 通知中心和桌面 Popover 中的系统公告点击后进入详情页；治理通知继续跳转到原有目标页面。
- [x] 公告正文保留换行，不渲染未经净化的 HTML；移动端无水平溢出。

## 发布影响

- 预期版本影响：`无需单独发布`
- migration / 环境变量 / 部署顺序：复用现有 `announcement`、`notification` 和 `notification_recipient` 字段，无新增 migration 或环境变量。
- 兼容性与回滚边界：只回滚公告详情路由、通知目标解析、服务方法、测试和任务文档；保留 M5.0 已存在的通知数据和公告数据。

## 测试

- 单元测试覆盖公告目标地址解析、公告编号校验和服务错误分支。
- 集成测试覆盖收件人快照隔离、详情读取、进入即已读、重复进入幂等和 suspended 用户读取已收到公告。
- E2E 覆盖通知中心与 Popover 进入详情页、完整正文、可选链接、未读数量减少、匿名访问和非收件人访问保护。
- 验证命令：`pnpm check:conventions`、`pnpm typecheck`、`pnpm lint`、`pnpm test`、`pnpm test:integration`、`pnpm test:e2e`、`pnpm build`。

## 风险 / 回滚

- 公告收件人快照和当前账号状态若混用，可能错误拒绝已送达公告；授权查询必须只依赖收件人关系。
- 详情页进入即已读可能让用户仅打开页面就清除未读状态；该行为与现有带链接通知保持一致。
- 回滚时保留通知和公告表，不删除生产数据卷；旧版本继续显示现有摘要并使用原有链接行为。
