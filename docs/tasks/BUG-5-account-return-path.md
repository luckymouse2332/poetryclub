# BUG-5 账户子页面保留安全返回地址

## 背景

M5.1 新增账户二级导航布局后，匿名访问 `/account/security` 或 `/account/poems` 时，布局先以固定的 `/account` 调用认证策略，导致登录页的 `next` 参数丢失具体子页面。该回归破坏了既有登录后返回原页面的行为，并可能影响后续子页面流程。

## 范围

- [x] 移除账户布局层对固定 `/account` 返回地址的认证调用。
- [x] 保留各账户页面自身的认证和对象级授权，让页面继续传入准确的返回地址。
- [x] 通过现有账户安全和诗作管理 E2E 验证匿名访问、登录返回和登出流程。

## 非目标

- [x] 不改变账户二级导航的视觉结构或入口顺序。
- [x] 不放宽账户页面、诗作页面或账户写操作的认证授权。
- [x] 不新增数据库、migration、环境变量或外部服务。

## 架构边界

- `src/app/account/layout.tsx` 只负责账户区域的布局和导航，不承担页面认证。
- 认证、权威用户状态和对象级授权继续由各页面或服务端入口独立执行。
- 匿名访问必须由具体页面使用准确的 `returnTo` 触发登录重定向。

## 验收条件

- [x] 匿名访问 `/account/security` 的登录地址保留 `next=/account/security`。
- [x] 匿名访问 `/account/poems` 的登录地址保留 `next=/account/poems`。
- [x] 账户安全、诗作管理和登出 E2E 不出现回归。

## 发布影响

- 预期版本影响：`无需单独发布`
- migration / 环境变量 / 部署顺序：无。
- 兼容性与回滚边界：仅回滚账户布局和对应任务文档，不影响通知数据或认证契约。

## 测试

- 运行 `pnpm typecheck`、`pnpm lint`、`pnpm test` 和 `pnpm test:e2e`。

## 风险 / 回滚

- 布局不再提前认证后，页面必须继续保留自身认证调用；通过全量 E2E 检查避免出现匿名渲染账户内容。
- 如回归，只回滚布局认证调用修复，不回滚 M5 通知功能。
