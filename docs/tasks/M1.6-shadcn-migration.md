# M1.6：自定义 UI 组件迁移到 shadcn/ui

## 背景

M1.5 建立了设计 Token 与基础组件，但 `src/components/ui` 下的 Button、Badge、Input、Textarea、FormField、Surface、EmptyState 都是手写实现，只是「看起来像 shadcn」：目录约定、`components.json`、CVA 和 `cn()` 都在，组件本身却没有 shadcn/ui 的结构（`data-slot`、Field 家族、Radix 无头原语）。后续 M2—M4 要增补 Dialog、Select、Tabs 等交互组件时，手写基线会与 shadcn 上游产生分叉，无障碍行为也要重复实现。

本任务把既有自定义组件迁移到 shadcn/ui 的无头组件基线上，**不改变任何视觉样式与组件逻辑**。`docs/design-system.md` 的 Token 与状态规范仍然优先于 shadcn 默认样式。

同时修复合并 `feat/m1-5-visual-foundation` 时带入的一处既有回归（见「既有回归修复」）。

- [x] 用 shadcn `Empty` 家族取代自定义 `EmptyState`，删除被取代的文件；`Surface` 保留为项目自有组件（见「组件归类」）。

- [x] 依赖从 `@radix-ui/react-slot` 切换到 shadcn 当前使用的统一包 `radix-ui`。

## 组件归类

「迁移到 shadcn」在本项目里不等于「每个文件都能在上游找到同名源码」。实际归类如下，
`docs/design-system.md` 第 10 节的实现基线表是这张表的规范化版本：

| 组件 | 与上游的关系 | 说明 |
| --- | --- | --- |
| `card` | 上游同构 | Card / CardHeader / CardTitle / CardDescription / CardAction / CardContent / CardFooter，结构与 `data-slot` 照搬上游 |
| `empty` | 上游同构 | 仅 `EmptyTitle` 渲染 `h3` 而非 `div`（设计系统第 11 节的语义化标题要求） |
| `field` | 上游同构 | 10 个导出全部补齐；纵向节奏保留项目的 `space-y-1.5`（见「已知问题与取舍」） |
| `label` | 上游同构 | Radix `Label.Root` |
| `separator` | 上游同构 | Radix `Separator.Root`，`FieldSeparator` 依赖 |
| `spinner` | 上游同构 | 与上游一致 |
| `button` | 上游同构 + 项目变体 | 上游的 cva + Slot 结构，variant / size 换成项目语义，额外增加 `loading` |
| `badge` | 上游同构 + 项目变体 | 上游结构，6 个项目语义变体 |
| `input` / `textarea` | 上游同构 + 项目变体 | 上游本身就是纯 HTML + Tailwind，无无头原语可迁移；类名换成项目 Token |
| `surface` | 项目自有 | 上游没有对应组件。承载层级（variant default/paper/muted + padding），与 Card 职责分离 |
| `form-field` | 项目自有 | 上游没有对应组件。在 `Field` 家族之上封装 label / description / error / `aria-describedby` 关联 |
| `icon-button` | 项目自有 | 上游没有对应组件。`Button size="icon"` 之上强制 `aria-label`、loading 时隐藏业务图标 |

需要说明的事实：在本组件集合内，上游 shadcn 自己只在两处使用 Radix 无头原语
（`Slot` 用于 button / badge 的 `asChild`，`Label`）；`input` / `textarea` / `card` / `empty` / `badge`
在上游就是普通 HTML + Tailwind，不存在「可迁移的无头组件」。本任务把这两处 Radix 用法补齐，
并因 `FieldSeparator` 新增了第三处（`Separator`）。

## 非目标

- 不改变任何视觉样式、间距、颜色、字号与交互逻辑。
- 不引入当前没有调用点的 shadcn 组件（Dialog、Select、Tabs、Sonner 等）。
- 不为了「看起来更 shadcn」而删除上游没有对应物的项目自有组件（`Surface` / `FormField` / `IconButton`）。
- 不改动认证、授权、会话、跳转、数据库与 migration。
- 不修改 `src/server`、`src/features` 的业务逻辑（仅更新组件导入与 JSX 标签名）。
- 不改变 `docs/design-system.md` 的 Token 定义与设计规范本身。
- 不自动继续进入 M2。

## 架构边界

- 迁移只影响 `src/components/ui`、`src/components` 与调用组件的 `src/app` / `src/features` 视图层；`app → features → server`、`components → lib` 的依赖方向不变。
- `src/components/ui` 仍是纯 UI，不得引入 feature 模块或读取会话；`Label` / `Field` 因使用 Radix 客户端原语标记 `"use client"`，但不获取任何数据。
- shadcn 组件源码可以按设计系统改写，但改写点必须在文件顶部注释中写明与上游的差异。
- 颜色与字号只使用 `docs/design-system.md` 定义的语义 Token，不因迁移引入 shadcn 默认的 `bg-background` / `text-muted-foreground` 之外的新色值来源。
- 不改变 Server Component 默认策略：Button、Badge、Card、Surface、Empty、Input、Textarea 保持无 `"use client"`；
  `Label` / `Field` / `Separator` 因 Radix 客户端原语标记 `"use client"`，`FormField` 随 `Field` 一并成为客户端组件。

## 测试

- 新增 `tests/unit/ui-components.test.ts`：12 个用例、31 个快照，覆盖 Button 4 变体 × 4 尺寸、loading / disabled / className / tab / `asChild`、IconButton、Badge 6 变体、Input / Textarea 默认与禁用 / 错误态、FormField 基础与完整态、Surface 3 变体 × 4 内边距、Card 子组件组合、Field 家族组合与 `errors` 去重、Empty 标题与完整态、PageContainer / PageHeader / Section。
- 迁移验证方法：在迁移前用同一份变体矩阵渲染出基线 DOM，迁移后重新渲染并逐行比对，确认差异仅为上述等价项；随后把迁移后的结果固化为提交进仓库的快照，作为后续改动的回归闸门。快照变化必须人工确认后再用 `pnpm test -u` 更新。
- 既有测试全部保留：单元测试 7 个文件 54 个用例，E2E 16 个用例。
- 最终命令结果：`pnpm typecheck` 通过；`pnpm lint` 通过；`pnpm test` 8 文件 66 用例通过；`pnpm test:e2e` 16/16 通过；`pnpm build` 通过（8 条路由）；`pnpm db:check` 通过。
- 环境说明：E2E 需要本地 PostgreSQL；本次使用既有 Docker Compose `db` 服务（`127.0.0.1:15432`），Playwright 基址仍为 `http://localhost:4000`。

## 已知问题与取舍

- `tailwind-merge` 不认识项目在 `@theme` 中自定义的字号类（`text-display` / `text-page-title` / `text-section-title` / `text-body-lg` / `text-body` / `text-label` / `text-caption`），会把它们当作文字颜色类，与 `text-*` 颜色类同时经过 `cn()` 时被丢弃。为保证「样式不变」，`field.tsx` 与 `empty.tsx` 中受影响的字号使用未合并的前缀写法，并在 `src/lib/utils.ts` 记录了该限制。后续可用 `extendTailwindMerge` 注册这些字号，届时必须重新核对受影响组件的实际字号。
- `IconButton` / `FormField` / `Surface` 不是 shadcn 上游组件，是项目自有封装；保留而非删除，避免改变既有可访问性契约与承载层级语义。
- 一次返工：初版把自定义 `Surface` 直接改名为 `Card` 并保留 `variant` / `padding`，这既不是上游 Card，也让文档里「以 shadcn 源码为基线」的说法站不住。
  返工后 `card.tsx` 恢复为真正的上游 Card（7 个子组件、无 variant），承载层级职责回到独立的 `surface.tsx`，
  调用点（`src/app/page.tsx`、`src/app/account/page.tsx`、`src/features/auth/components/auth-form.tsx`）改回 `Surface`，渲染类名不变。
- `field.tsx` 初版只导出 4 个成员，返工后补齐上游 10 个导出，并新增 `separator.tsx` 供 `FieldSeparator` 使用。
  期间修正了一处 HTML 合法性问题：`FieldError` 由 `<p>` 改为上游的 `<div>`，避免多条错误时 `<ul>` 嵌套进 `<p>`；`Field` 根节点补上上游的 `role="group"`。
- `Field` 纵向排布保留项目的 `space-y-1.5`，未采用上游的 `flex flex-col gap-3`：后者会把表单行距从 0.375rem 拉到 0.75rem，属于视觉变更，需要单独的设计任务。
- `Empty` 的 `EmptyTitle` 渲染 `h3` 而非上游的 `div`，以满足设计系统第 11 节的语义化标题要求。

## 风险 / 回滚

- 风险：快照测试会把类名顺序也纳入回归范围，未来正常的样式调整会导致快照失败；这是有意的闸门，但要求改动者确认差异后再更新快照，不得无脑 `-u`。
- 风险：`radix-ui` 统一包与逐包 `@radix-ui/react-*` 混用会导致重复实例；后续新增组件必须继续从 `radix-ui` 导入。
- 风险：`Label` / `Field` / `Separator` 引入 `"use client"`，如果未来把它们用在纯静态大页面中会扩大客户端包；当前只在认证表单路径使用，影响可忽略。
- 风险：`Card` 与 `Surface` 职责相近，容易被误用成同一个东西；`docs/design-system.md` 第 10 节已写明分工，新增卡片式区块时必须先确认要的是「承载层级」还是「带标题分区的卡片」。
- 确认：本任务未修改 `src/server/db/schema`、`drizzle/` 或任何 migration，未执行数据库操作（`pnpm db:check` 仅做一致性校验）。
- 确认：本任务未进入诗作领域，未新增业务模块或未实现功能入口。
- 回滚：`git revert` 本次提交即可恢复手写组件；依赖需同步回退到 `@radix-ui/react-slot`。没有数据库回滚步骤。
