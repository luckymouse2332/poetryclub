# M0.1：宿主机 Caddy 生产部署调整

## 背景

当前生产 Compose 同时编排应用、PostgreSQL、migration 与 Caddy，但实际服务器上的 Caddy 由宿主机独立运行。容器内 Caddy 会重复占用 80/443 端口，也让证书与代理配置的归属不符合真实部署环境。本任务依据实际部署拓扑修正生产配置与说明。

## 范围

- [x] 从生产 Compose 中移除 Caddy 服务及其专用网络和数据卷。
- [x] 将 Next.js 应用通过宿主机回环地址发布到 `4000` 端口，供宿主机 Caddy 反向代理。
- [x] 同步环境变量示例、架构文档、部署说明和项目 README。
- [x] 验证 Compose 配置及项目质量命令。

## 非目标

- [x] 不代替服务器管理员写入或重载宿主机的实际 Caddy 配置。
- [x] 不调整 PostgreSQL、migration、管理员初始化或业务功能。
- [x] 不把数据库端口发布到宿主机。

## 架构边界

生产环境仍为单个 Next.js 应用容器和单个 PostgreSQL 实例，migration 继续作为一次性容器运行。PostgreSQL 只存在于 Compose 内部网络。应用端口只绑定宿主机回环地址，公网 TLS 与安全响应头由宿主机 Caddy 负责。

## 验收条件

- [x] `deploy/compose.production.yaml` 不再定义 Caddy 服务、Caddy 卷或前端网络。
- [x] 应用发布为 `127.0.0.1:4000:3000`，容器健康检查仍检查实际监听端口。
- [x] 部署文档明确宿主机 Caddy 应代理 `127.0.0.1:4000`，并不再声称 Compose 管理证书。
- [x] 生产环境示例不再要求仅供容器 Caddy 使用的变量。
- [x] `pnpm typecheck`、`pnpm lint`、`pnpm test`、`pnpm build` 与 Compose 配置校验通过。

## 测试

使用生产环境示例执行 `docker compose config`，确认最终只发布应用的宿主机 `4000` 端口。`pnpm typecheck`、`pnpm lint`、187 项单元测试和 `pnpm build` 均通过，部署验收已通过。

## 风险 / 回滚

宿主机 Caddy 必须在切换后及时指向 `127.0.0.1:4000`，否则域名会暂时无法访问。回滚时可恢复旧版 Compose 和容器 Caddy 配置，但需要先确认 80/443 端口没有被宿主机 Caddy 占用。
