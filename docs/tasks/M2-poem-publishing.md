## 架构边界

- 路由页面保持薄层；诗作业务组件归属 `src/features/posts`，服务端数据访问/领域规则归属 `src/server`，数据库只能由 server-only 模块访问。
- 所有写入口独立调用既有 `requireCurrentUser()`，不接收或信任客户端作者、状态及发布时间。
- 私有读取按 `id + authorId` 查询；更新、发布、撤回和删除按 `id + authorId` 以及必要的当前状态做原子条件更新，避免 IDOR 和竞态状态转换。
- 公开查询在数据库条件中限定 `published` 且 `publishedAt` 非空；草稿、撤回、不存在作品对公开详情统一为 404。
- 所有列表分页或使用固定小上限；公开摘要在查询层截断，不读取/传输整篇正文。
- Server Action 参数与 FormData 均视为不可信输入并经 Zod 校验；只返回 UI 所需的稳定错误状态，不返回数据库实体或内部错误。
- 当前项目未启用 Cache Components 且未缓存数据库查询，本任务保持按请求读取；写后只刷新受影响的首页、公开及账户路径。
- 用户正文按 React 纯文本渲染并使用 `white-space: pre-wrap`，禁止 `dangerouslySetInnerHTML`。

## 数据模型决策

- `poem.id` 与现有用户主键一致使用 `text`，由服务端 `crypto.randomUUID()` 生成。
- `title`、`body` 为必填纯文本；`context`、`occurredAt` 可空。
- `authorId` 引用 `user.id` 并级联删除；状态仅为 `draft | published`。
- `createdAt`、`updatedAt` 沿用现有 `timestamp + Date` 约定；`publishedAt` 首次发布写入，撤回及再次发布保留。
- `creationToken` 是不进入 DTO 的幂等键，与作者组成唯一约束，确保同一新建表单重复提交只对应一个草稿。
- 数据库检查约束保证 `published` 行必有 `publishedAt`；服务端原子条件更新保证合法转换和草稿删除语义。

## 风险 / 回滚

- 风险：状态竞态或所有权条件遗漏会造成越权/非法转换；通过单条条件更新、受影响行数检查及安全测试降低风险。
- 风险：公开查询错误或缓存会泄露已撤回内容；公开条件统一下沉至服务端查询，当前保持不缓存数据库查询并在写后精确刷新路径。
- 风险：超长正文影响 Action 请求和页面；正文限制在 20,000 字符内，低于 Next.js 默认 1MB Action 上限，列表仅查询摘要。
- 风险：E2E 依赖 PostgreSQL 与 Chromium；缺失时如实记录，不以跳过测试虚报完成。
- 已知限制：M2.0 不提供编辑历史、审核/归档流程或已发布作品直接删除；公开列表使用 offset 分页，数据规模增长后可另行评估游标分页。
- 已知限制：`updatedAt` 与现有认证表一致由 Drizzle/应用层维护，不额外建立数据库触发器；绕过应用直接执行 SQL 不属于受支持写入路径。
- 回滚：先回滚应用代码，再回滚新增 migration（仅删除 `poem` 表与状态 enum）；不修改现有认证表和生产数据。
