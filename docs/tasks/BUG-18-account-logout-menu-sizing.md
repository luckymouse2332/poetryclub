# BUG-18：账户登出菜单项高度修复

## 背景

用户发现账户菜单的登出项明显高于其他项。DropdownMenuItem 的 asChild 指向外层 form，内层 button 另有 44px 最小高度及内边距，造成 20px 菜单内边距叠加，整体达到 64px。

## 范围

- [x] 将菜单项语义与样式直接应用到登出 button，form 只负责提交。
- [x] 保留危险色、44px 点击区域和原有登出流程。
- [x] 验证桌面与手机行高一致及键盘登出。

## 非目标

不改变认证、会话撤销、服务端登出规则或其他菜单组件；不提交或推送。

## 架构边界

仅调整 auth 中账户导航组合与相关浏览器验收；继续复用 shadcn/Radix 的 asChild、data-slot 和焦点行为，保持 logoutAction 与接口请求不变。

## 验收条件

- [x] 登出项为实际 button，行高与相邻菜单项一致且不低于 44px。
- [x] 图标、文字起点和点击区域一致，不再嵌套叠加内边距。
- [x] 鼠标悬停、键盘登出及失效会话回归通过。

## 发布影响

- 预期版本影响：无需单独发布。
- migration / 环境变量 / 部署顺序：无。
- 兼容性与回滚边界：原业务接口不变，回滚菜单组合即可。

## 测试

更新现有认证回归的桌面/手机高度断言，并通过菜单键盘触发登出；运行 auth-flow、typecheck、lint、规范检查，查看菜单截图。

- auth-flow：10 项通过，包含 Enter 触发实际登出、自动恢复游客导航、重复登出与旧会话拒绝。
- 桌面 1440px、手机 390px：登出与账户信息均为 44px，横向内边距一致；人工查看两份菜单截图通过。
- typecheck、lint、check:conventions、git diff --check 通过。
- 尺寸验收等待入场缩放结束再测量；登出验收等待按钮自行导航，避免测试强制刷新与同地址导航竞争。
- M6.8 全量回归补齐 poem-flow 中的登出定位：实际交互元素沿用 Radix 的 menuitem 角色，鼠标点击断言使用该角色。

## 风险 / 回滚

保留 form 的原 Server Action 与按钮点击处理，不引入第二条登出逻辑。菜单角色直接落到按钮上，保持原键盘与焦点管理。
