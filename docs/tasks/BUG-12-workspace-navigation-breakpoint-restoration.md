# BUG-12 工作区导航断点恢复

## 背景

`BUG-10` 将成员与管理工作区在 `lg` 以上全部改为页面顶层横向二级导航，导致宽屏失去 M6.0 已建立的常驻侧栏和工作区分栏。用户提供的中等宽度与大屏截图明确要求保留两种布局：中等宽度使用横向导航，大屏恢复原有侧边导航。

## 范围

- [x] 在 `lg` 至 `xl` 之间显示页面顶层横向二级导航。
- [x] 在 `xl` 起恢复约 224px 的工作区侧栏，并隐藏横向导航。
- [x] 成员与管理工作区共用同一套断点和活动路由规则，管理侧栏包含 M7 的评论入口。
- [x] 更新设计系统、发布变更日志和响应式 E2E。

## 非目标

- [x] 不改变小于 `lg` 的全站 Sheet、账户正文内导航或移动端信息架构。
- [x] 不改变导航链接权限、路由、业务服务或数据结构。
- [x] 不修改页面卡片、字体、颜色或其他无关视觉样式。

## 架构边界

`WorkspaceShell` 继续负责响应式工作区骨架，活动路由判断保留在小型 Client Component 中。管理与账户 feature 只提供导航数据，`src/app` 布局只负责组合，不复制断点或导航样式。

## 验收条件

- [x] 390px 下管理工作区不出现重复二级导航，账户正文内导航保持可用。
- [x] 1024px 下只显示横向二级导航，正文保持单列且无水平溢出。
- [x] 1280px 与 1440px 下只显示侧边导航，侧栏位于正文左侧并保留当前项反馈。
- [x] 管理侧栏显示总览、诗作、评论、用户、邀请码、公告和审计七个入口。
- [x] typecheck、lint、相关 E2E 与设计 QA 通过。

## 发布影响

- 预期版本影响：`PATCH`，作为 `v1.5.0` 发布阻断修复一并交付。
- migration / 环境变量 / 部署顺序：无。
- 兼容性与回滚边界：仅修改响应式布局与文档，可单独回滚到横向导航实现。

## 测试

已更新账户与管理工作区断点 E2E，在 390px、1024px、1280px 和 1440px 检查导航唯一性、变体、活动项、左右位置及水平溢出。相关 Chromium E2E 共四项通过；1158px 与 1521px 视觉截图完成同尺寸并排比较，`design-qa.md` 最终结果为 `passed`。

## 风险 / 回滚

主要风险是 1280px 同时渲染两套导航、侧栏宽度压缩正文或恢复组件时遗漏 M7 评论入口。通过互补 Tailwind 断点、共享导航数据和多视口 E2E 控制；回滚只需恢复 `WorkspaceShell` 的单一横向导航分支。
