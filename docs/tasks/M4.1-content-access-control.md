# M4.1 内容访问权限控制

## 背景

当前诗作只有作者发布状态和管理员治理状态，所有已发布且未隐藏的作品都面向游客公开。产品路线需要支持“公开”和“仅成员可见”，并在游客直达受限作品时提供安全的登录入口。

## 范围

- [x] 为诗作增加 `public | members_only` 访问范围和版本化 migration。
- [x] 让 active 成员和管理员在现有首页、诗作列表和详情中读取两类已发布作品。
- [x] 让游客只能读取公开作品；游客直达仅成员作品时显示不泄露作品内容的登录弹窗。
- [x] 在新建和编辑表单中要求作者明确选择访问范围，并支持已发布作品即时切换。
- [x] 在作者、管理员和读者页面显示访问范围标签，并补充授权、泄露防护和响应式测试。

## 非目标

- [ ] 不实现评论、点赞、收藏、通知、诗集、班史时间轴、共同创作或音频上传。
- [ ] 不新增社区成员关系、复杂角色组、分享令牌或公开 API。
- [ ] 不改变作者发布/撤回语义、管理员隐藏语义、宿主机 Caddy、环境变量或版本号。

## 架构边界

- 页面保持薄层；作品访问范围、读取者判定和状态组合规则位于 `src/server/services`、`src/server/policies` 与 `src/server/validation`。
- 每个 Server Action 重新执行身份认证、对象级授权、Zod 输入校验、业务规则校验和错误处理。
- 只有 active member/admin 能读取成员作品；suspended 账号沿用既有只读访问，但成员作品按不可读处理。
- 公开查询必须在数据库条件中同时限定已发布、未隐藏、发布时间存在和读取者允许的访问范围。
- 受保护详情的游客响应不得包含标题、正文、背景、作者或日期；请求态读取使用 React `cache`，不使用跨用户持久缓存。
- 数据库 schema 改动必须生成并提交版本化 SQL migration；客户端不得直接访问数据库或信任客户端身份字段。

## 验收条件

- [x] 旧作品回填为公开，新建作品没有预选范围且未选择时不能保存。
- [x] 匿名首页和 `/poems` 不出现成员作品；active 成员和管理员在相同列表中看到两类作品并看到标签。
- [x] 游客直达成员作品只看到通用模糊占位、登录表单和返回列表入口，登录后回到原地址。
- [x] suspended 账号不能读取成员作品；草稿、撤回、隐藏和不存在作品继续统一不可读。
- [x] 作者可以切换已发布作品的访问范围，切换后所有受影响路径立即反映新结果。
- [x] 跨用户、匿名和伪造字段的写操作失败且不改变作品数据。
- [x] 通过 390px 响应式、键盘焦点、migration、typecheck、lint、unit、integration、E2E 和 build 验证。

## 发布影响

- 预期版本影响：`MINOR`
- migration / 环境变量 / 部署顺序：新增 `poem_visibility` 与 `poem.visibility`；无新环境变量。部署必须先完成 migration，再启动使用新字段的应用。
- 兼容性与回滚边界：旧数据保持公开；访问范围字段保留数据库兼容默认值，代码回滚不会使旧作品失去读取。生产环境不使用 schema push，也不删除已执行 migration。

## 测试

- 单元：访问范围 schema、缺失/非法值、表单字段错误、查询读取者范围纯函数。
- E2E：匿名/active/admin/suspended 读取、登录弹窗返回、访问范围切换、旧作品兼容、隐藏覆盖、跨用户与伪造写入、390px 布局和键盘焦点。
- 验证命令：`pnpm check:conventions`、`pnpm typecheck`、`pnpm lint`、`pnpm test`、`pnpm db:check`、`pnpm test:integration`、`pnpm test:e2e`、`pnpm build`。

## 风险 / 回滚

- 风险：遗漏某个公开查询会泄露成员作品；所有首页、列表和详情读取统一经过服务端访问谓词，并用游客 HTML 断言防止内容进入响应。
- 风险：状态切换后页面缓存残留；更新、发布、撤回和管理员治理写入精确失效首页、列表、详情和作者路径。
- 风险：迁移与旧代码并行运行；数据库保留公开默认值，应用写入口仍强制显式校验，部署按 migration 成功后启动新应用。
- 回滚：保留新增字段和 migration，回滚应用代码后旧作品继续按公开默认读取；禁止在生产直接删除列或重写历史 migration。
