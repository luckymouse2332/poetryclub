# M8 诗作特辑与连续阅读

## 背景

现有网站可以独立发布和阅读诗作，但无法把相关作品按明确顺序整理成一组持续维护的内容。本任务新增统一称为“特辑”的编排能力，让正常成员整理当前有权阅读的已发布作品，并沿用既有的访问控制、管理治理和纯文本安全边界。

## 范围

- [x] 新增特辑与特辑项目 Schema、版本化 migration、索引和约束。
- [x] 实现特辑草稿、编辑、发布、撤回、删除、收录、移除和相邻排序。
- [x] 实现公开与成员特辑访问控制、分页目录和逐篇连续阅读。
- [x] 实现成员工作区、公开入口、全站导航和管理员治理入口。
- [x] 实现隐藏、恢复、通知和审计事务，失效作品在公开读取中安全跳过。
- [x] 更新产品、架构、设计系统、隐私、条款和 About 页面。
- [x] 补齐单元、集成和 E2E 覆盖并完成质量验证。

## 非目标

- [x] 不新增文章模型、封面、附件、Markdown、全文搜索或开放 API。
- [x] 不实现共同编辑、收录确认或收录通知。
- [x] 不在功能分支修改版本号、CHANGELOG、发布标签或远程分支。

## 架构边界

页面保持薄层，特辑领域规则集中在 `src/server/services` 与 `src/server/validation`，交互组件和 Server Actions 位于 `src/features/collections`。所有写入口独立校验权威身份、对象所有权、输入和状态转换。特辑目录、作品选择器和管理列表全部分页；用户文本以纯文本显示。公开读取只返回当前读者有权读取且状态有效的作品，失效收录记录不泄露标题或原始数量。

## 验收条件

- [x] active 成员可以幂等创建自己的特辑草稿，编辑元数据和有序目录，并完成发布、撤回和未发布草稿删除。
- [x] 公开特辑只能收录公开作品，仅成员特辑可以收录当前成员可读作品；其他用户、suspended 账号和越权调用不能修改特辑。
- [x] 游客只能浏览公开特辑，active 成员和管理员可以浏览仅成员特辑；无权直达成员特辑时不泄露标题与简介。
- [x] 特辑目录分页，逐篇阅读提供上一篇、下一篇和返回目录；撤回、隐藏或范围不兼容的诗作会被安全跳过。
- [x] 管理员隐藏与恢复特辑时在同一事务写入治理状态、最小通知和审计记录。
- [x] 390、1024、1440px 下页面可读、可操作且无水平溢出，纯文本不能作为 HTML 执行。
- [x] 约定检查、类型检查、Lint、单元、集成、E2E、数据库检查、生产构建和空库 migration 验证通过。

## 测试

单元测试覆盖字段限制、ID、分页、动作错误映射和访问判断。集成测试覆盖幂等、所有权、访问范围、状态转换、分页、相邻排序、他人作品收录、失效项目过滤以及治理事务。E2E 覆盖游客、成员、管理员、连续阅读、登录门槛、键盘操作、About 更新和响应式布局。

验收结果：`check:conventions`、`typecheck`、`lint`、`db:check` 和生产构建通过；单元测试 243 条、集成测试 27 条、E2E 74 条全部通过。独立 Docker Compose 项目中的空 PostgreSQL 已成功应用全部 migration，随后已移除临时容器、网络和数据卷。

## 风险 / 回滚

主要风险是并发排序造成位置冲突、他人作品状态变化导致信息泄露、成员特辑通过通知暴露文本，以及治理和读取规则不一致。通过特辑行锁、唯一约束、统一服务查询、最小通知 payload 和事务化审计控制。应用回滚时保留新增数据结构，后续版本可继续恢复功能。
