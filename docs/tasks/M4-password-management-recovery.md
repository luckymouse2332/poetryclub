# M4.0 账户密码管理与找回闭环

## 背景

项目已经支持邀请注册、邮箱密码登录、服务端会话读取、登出和账户页，但真实用户忘记密码后没有可用的自助恢复流程，已登录用户也无法主动更换密码。本任务在现有 Better Auth、Drizzle ORM、PostgreSQL 和宿主机 Caddy 部署边界内补齐账户密码安全闭环。

## 目标

- [x] 已登录用户可以在受保护的账户安全页验证当前密码并修改密码。
- [x] 用户可以提交统一响应的忘记密码请求，并通过中文事务邮件获得一小时有效的重置链接。
- [x] 用户可以通过 Better Auth 官方令牌流程重置密码，成功后全部旧会话失效并重新登录。
- [x] 运维人员可以在服务器终端使用受控脚本执行紧急账号恢复。
- [x] 注册、修改密码和重置密码共用同一组长度规则与错误边界。

## 范围

- [x] 增加 `/account/security` 服务端保护页面和修改密码表单。
- [x] 在登录页增加忘记密码入口，并增加 `/forgot-password` 页面。
- [x] 增加 `/reset-password` 页面，处理有效、缺失、无效、过期、已使用 token 及 Better Auth 错误参数。
- [x] 配置 Better Auth 1.6.25 的密码重置、会话撤销、密码长度和相关限流能力。
- [x] 建立可替换的事务邮件抽象、生产供应商适配层和测试 outbox。
- [x] 增加邮件、公开站点地址及部署所需环境变量校验和示例。
- [x] 检查宿主机 Caddy 转发头与 Better Auth 客户端 IP 获取方式。
- [x] 增加仅服务器终端可执行的紧急密码恢复脚本，并在事务中撤销全部会话。
- [x] 补充 Vitest、集成测试、Playwright E2E、部署和运维文档。

## 非目标

- [x] 不实现修改邮箱或邮箱验证体系重构。
- [x] 不实现双因素认证、OAuth、Magic Link 或账户注销。
- [x] 不实现密码历史或复杂密码组成规则。
- [x] 不增加管理员在网页中替任意用户修改密码的按钮或 HTTP 接口。
- [x] 不建设通用安全审计平台，不改版首页、关于页或整体导航。

## 安全约束

- 所有密码修改、重置请求和重置提交均使用 Better Auth 当前安装版本的官方流程，不自行验证或拼接密码哈希，不自行生成、签名、查询或失效重置 token。
- 修改密码必须验证当前密码；确认密码只在应用层校验，不传给 Better Auth；成功时仅保留当前会话。
- 邮箱是否存在不得通过文案、状态码、前端行为或明显时序差异泄露；邮件失败不得改变统一的公开响应。
- 重置 token 不进入日志、错误监控、analytics 或客户端持久化，取得后不得传播给无关链接。
- 密码重置成功后撤销全部旧会话；修改密码成功后撤销除当前会话以外的其他会话。
- 生产环境必须使用真实事务邮件供应商；缺少关键配置时尽早失败，禁止退化为控制台输出重置链接。
- 只有显式开发或测试策略可以使用受控日志或测试 outbox，异步邮件失败必须被捕获和记录。
- 不盲目信任任意转发头，只按当前宿主机 Caddy 与 Docker 拓扑处理可信客户端 IP。
- 密码、完整 token、完整重置 URL、credential account 和服务端异常堆栈不得发送到浏览器或写入应用日志。
- 紧急恢复只允许服务器终端执行，通过邮箱精确定位唯一 credential account，密码从安全输入或环境变量读取，密码更新与会话撤销必须具备事务性。

## 架构边界

- `src/app` 仅负责路由、服务端保护和页面组合；验证、邮件、认证错误映射和服务端操作放入 `src/features/auth` 或 `src/server`。
- 默认使用 Server Components；仅交互表单使用 Client Component。
- 数据库访问仅位于 `src/server` 和服务器脚本，客户端不得接触数据库、邮件供应商或 credential account。
- 复用现有 shadcn/ui、`FormField`、暖纸 Token、页面宽度和排版，不新增重复 UI 基础组件。
- 所有服务端入口独立完成认证、对象级授权、Zod 校验、业务规则校验和安全错误处理。
- Schema 如需变更必须提交版本化 SQL migration；若 Better Auth 现有 verification 表足够则不制造无必要迁移。

## 验收条件

- [x] 正确当前密码可以修改密码，旧密码失效，新密码可登录。
- [x] 修改密码后其他会话失效，当前浏览器会话继续有效。
- [x] 当前密码错误、确认密码不一致或新密码不符合统一规则时不修改密码，并显示安全、明确的错误。
- [x] 匿名用户访问 `/account/security` 时按现有 `next` 参数规则跳转登录。
- [x] 忘记密码对存在和不存在邮箱显示等价响应，测试环境不发送真实邮件。
- [x] 有效 token 可以重置密码；缺失、无效、过期或已使用 token 不允许提交或再次修改密码。
- [x] 重置成功后全部旧会话失效，旧密码不能登录，新密码可以登录，并跳转到带一次性成功提示的登录页。
- [x] token 有效期为一小时；日志和错误对象不包含明文密码、完整 token 或完整重置 URL。
- [x] 生产缺少邮件关键配置时尽早失败，且生产路径不可能退化为日志发送重置链接。
- [x] 关键表单具备正确 label、autocomplete、禁用状态、字段错误关联、键盘焦点和移动端可用性。
- [x] 紧急恢复脚本只在服务器终端执行，精确更新唯一 credential account，并在同一事务撤销全部会话。
- [x] 注册、登录、登出、账户页、诗作和管理员治理没有回归。

## 风险 / 回滚

- 邮件供应商或环境变量错误会使生产密码找回不可用；通过启动期校验、独立适配层和部署清单降低风险。
- 反向代理头配置错误会影响限流准确性；只按已部署 Caddy 拓扑信任明确来源，不进行无关代理重构。
- Better Auth API 或内部哈希入口使用错误可能破坏认证；实现以锁定的 1.6.25 类型和源码为准，并用真实数据库集成流程验证。
- 异步邮件会带来失败不可见和未处理 Promise 风险；统一捕获、脱敏记录并保持外部响应一致。
- 回滚时可撤回页面、邮件和配置改动；若产生 migration，则必须使用单独回滚 migration，不改写已执行历史。

## 后续事项

- 当前生产只有一个应用容器，Better Auth 密码端点限流使用内存存储；未来横向扩容前需改为共享限流存储。
