# M3.9 移动端导航与区块标题短线

## 背景

当前刊头在 `sm` 断点后就让品牌与认证导航并排。登录态入口较多时，中等宽度视口会把“登出”单独挤到下一行，导航层次不稳定。用户同时要求参考示例，在首页“最新诗作”标题下增加一条克制的印章红短线。

## 范围

- [x] 调整主导航在手机、中等宽度和桌面视口下的布局。
- [x] 保持所有导航入口至少 44px 高，并避免单个入口孤立换行。
- [x] 在“最新诗作”标题下增加装饰短线。
- [x] 更新浏览器测试并检查无横向溢出。

## 非目标

- [x] 不改动导航入口、认证状态、登出 Action 或权限判断。
- [x] 不加入抽屉菜单、汉堡按钮或新的客户端状态。
- [x] 不改变诗作查询、首页内容与数据库行为。

## 架构边界

`SiteHeader` 和 `AuthNavigation` 继续保持 Server Component。变化限于纯 UI 布局、首页局部 CSS Module 和 E2E 断言，不新增组件或依赖。

## 验收条件

- [x] 390px 登录态导航以稳定网格排列，没有横向溢出，所有入口均可见且点击高度至少 44px。
- [x] 768px 与约 900px 宽度下，登录态导航不会把“登出”单独挤到下一行。
- [x] 1024px 及以上恢复品牌与导航并排布局。
- [x] “最新诗作”标题下显示宽度、颜色和间距稳定的装饰短线。
- [x] typecheck、lint、Vitest、相关 Playwright 和生产构建通过。

## 测试

扩展首页与认证 Playwright，检查导航在 390px、768px、920px、1024px 的排列、点击高度、横向溢出，以及“最新诗作”标题伪元素的计算样式。运行 `pnpm typecheck`、`pnpm lint`、`pnpm test`、相关 E2E 与 `pnpm build`。

验证结果：`pnpm typecheck`、`pnpm lint`、187 项 Vitest、首页与认证相关的 19 项 Playwright、`pnpm build` 全部通过。生产模式截图复核了 390px 刊头，品牌当前页短线位于品牌文字下方；浏览器截图同时复核了 920px 导航和“最新诗作”标题短线。

按项目流程调用了 `deepseek-review`。首次命令将该配置识别为子代理并回退到默认审查器；随后使用显式 DeepSeek 模型重新调用，只读审查在 120 秒后超时，未返回文本，也未写入工作区。人工聚焦审查未发现阻断级或严重问题。

## 风险 / 回滚

主要风险是断点调整影响匿名导航的留白或登录态按钮尺寸。回滚时恢复 `SiteHeader` 的原有 flex 类名并移除首页标题装饰类，不影响任何服务端逻辑。
