# M9.0 操作流程优化与重构

## 背景

项目扫描发现认证表单在 hydration 前可能以 GET 提交敏感字段；公告与作品编辑存在未保存内容和发布动作脱节；部分排序和分页反馈不符合实际状态。登录缺少邮箱验证码入口，注册尚未核验邮箱，错误反馈也不够醒目。本任务先修复现有操作问题，再扩展邮箱认证。

## 范围

- [x] 修复认证表单在 hydration 前的原生提交行为，避免敏感字段进入 URL。
- [x] 修复公告、诗作、特辑编辑与发布时的未保存内容问题。
- [x] 修复特辑排序边界反馈和评论分页状态反馈。
- [x] 增加注册邮箱验证和邮箱验证码登录，保留现有密码登录与邀请码规则。
- [x] 加强认证错误提示，复用现有 shadcn/Radix Popover，并保留可访问的表单错误信息。
- [x] 更新产品文档和必要测试。

## 非目标

- [x] 不改变现有角色、审核、内容可见性和邀请码准入政策。
- [x] 不更换认证框架、邮件供应商或 UI 组件体系。

## 架构边界

`app` 只保留薄路由入口；认证、内容与通知规则分别留在对应 `features` 与 `server` 模块。所有写入口独立校验身份、对象权限、Zod 输入和业务状态。验证码不写入客户端日志，验证限次与过期由服务端保障。复用现有 `radix-ui` 与 shadcn 组件；数据库结构若变更必须提交 SQL migration。

## 验收条件

- [x] 未 hydration 的密码表单不会把密码写入 URL。
- [x] 编辑后发布的内容与当前表单一致，离开未保存编辑时有明确反馈。
- [x] 排序和分页反馈与实际状态一致。
- [x] 注册需完成邮箱验证，已注册用户可用邮箱验证码登录；未注册邮箱不能绕过邀请码创建账户。
- [x] 验证码过期、错误、重试和同步发送请求失败均有清晰且可访问的提示；异步邮件供应商故障提供重发入口并由服务端脱敏记录。
- [x] 现有密码登录、找回密码和受限账号规则保持可用。

## 发布影响

- 预期版本影响：`MINOR`
- migration / 环境变量 / 部署顺序：`drizzle/0008_grandfather-existing-email.sql` 必须先于要求邮箱已验证的新认证代码运行。沿用现有 `verification` 表与邮件配置，无新增环境变量。生产 Compose 先完成 migration 再启动应用。
- 兼容性与回滚边界：迁移把升级前已有密码账号视为已验证，维持原有登录能力；升级后新账号必须完成邮箱验证。该历史兼容标记不能自动逆转；应用回滚仍保留密码登录。邮件异常时，新账号可重发验证码，旧账号不受影响。

## 测试

`pnpm db:check` 与本地 `pnpm db:migrate` 通过；`pnpm test:integration` 通过 27 项。`pnpm build` 使用非机密占位邮件配置通过。`pnpm check:conventions`、`pnpm typecheck`、`pnpm lint`、`pnpm test`（245 项）和 `git diff --check` 通过。完整 E2E 第二轮通过 75 项，2 项测试断言因 hydration 时序与旧文案失败、1 项串行依赖未运行；随后重跑受影响的三个文件，22 项全部通过。因此 78 项 E2E 均至少一次通过，修复后的三个文件全部通过。

## 风险 / 回滚

注册验证影响新账号准入，真实数据库 E2E 已覆盖邀请码消耗与验证码注册。发送邮件的异步供应商故障只能通过重试与服务端脱敏日志观察，首次注册的页面不能保证即时获知。内容动作合并已通过事务集成测试和重复提交 E2E。回滚时保留原有密码入口和已创建的用户数据。
