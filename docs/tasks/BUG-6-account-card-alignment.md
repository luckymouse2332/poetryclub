# BUG-6 账户页卡片对齐与表面层级修复

## 背景

账户首页桌面双栏中，左侧“基本信息”被 `Section` 默认的纵向间距向下推移，无法与右侧快捷操作栏的起点对齐；“我的作品”和“账户安全”又使用了不同的 Surface 变体，使两个同级入口呈现不同底色和阴影。

## 范围

- [x] 移除账户页左栏额外的章节上内边距，使“基本信息”与右侧首张快捷卡片顶部对齐。
- [x] 将“我的作品”和“账户安全”统一为相同的纸面 Surface。
- [x] 保留两个按钮现有的主次操作层级、链接目标和权限行为。
- [x] 补充桌面和移动端布局回归检查。

## 非目标

- [ ] 不修改账户数据、认证、权限判断或服务端查询。
- [ ] 不调整账户安全页、诗作管理页或其他工作区页面。
- [ ] 不重构共享 `Section`、`Surface` 或 `Button` 组件。

## 架构边界

改动限定在 `src/app/account/page.tsx` 及直接测试和 QA 记录。页面继续保持 Server Component，现有认证、用户状态查询、Badge 语义、导航链接和按钮层级保持不变。

## 验收条件

- [x] 1024px 以上双栏布局中，左侧章节起点与右侧第一张卡片顶部对齐，不再出现异常大块空白。
- [x] 两张快捷操作卡片使用相同背景、边框与阴影。
- [x] 移动端仍保持自然单列，没有水平溢出。
- [x] `pnpm typecheck`、`pnpm lint` 与 `pnpm build` 通过。

## 发布影响

- 预期版本影响：`PATCH`
- migration / 环境变量 / 部署顺序：无。
- 兼容性与回滚边界：仅账户页局部结构和 Surface 变体，可单文件回滚。

## 测试

新增独立账户页 E2E，通过服务端认证 API 建立管理员会话，验证 1440px 下左右首张卡片 `y` 坐标差不超过 1px，两张快捷卡片均为 `paper` 且计算后的背景、边框与阴影一致；390px 下页面无水平溢出。专项 E2E 1 项通过。

`pnpm check:conventions`、`pnpm typecheck`、`pnpm lint`、`pnpm test` 与 `pnpm build` 均通过；单元测试为 16 个文件、208 项测试全部通过。桌面与手机截图已完成并记录在 `design-qa.md`，最终结果为 `passed`。验证过程没有启动、停止或重启开发服务器。

## 风险 / 回滚

主要风险是移除 `Section` 后标题间距偏紧，或移动端快捷操作顺序变化。保留原有 DOM 顺序和 24px 标题到内容间距；若需回滚，恢复账户页原有 `Section` 包装和 `muted` 变体即可。
