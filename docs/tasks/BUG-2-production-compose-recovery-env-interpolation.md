# 生产 Compose 恢复变量插值修复

## 背景

生产 Compose 中的紧急账号恢复服务位于 `tools` profile，但其一次性输入使用了 Compose 的必填插值语法。Compose 会在筛选 profile 前展开全部服务变量，导致正常执行 `up -d --build` 时也要求填写紧急恢复邮箱和密码，阻塞生产部署。

## 范围

- [x] 允许普通生产部署在未启用紧急恢复工具时保持恢复变量为空。
- [x] 保留紧急恢复脚本对邮箱和密码的运行时严格校验。
- [x] 验证普通 Compose 配置和恢复工具配置均可正确解析。

## 非目标

- [x] 不修改数据库 Schema、migration 或现有数据。
- [x] 不改变紧急恢复脚本的密码更新和会话撤销逻辑。

## 架构边界

紧急恢复功能继续只存在于 `tools` profile 和服务器终端脚本中，不增加网页或 HTTP 入口。密码不写入仓库、任务文档或日志。

## 验收条件

- [x] `RESET_USER_EMAIL` 和 `RESET_USER_PASSWORD` 为空时，普通生产 Compose 配置检查通过。
- [x] 显式提供恢复变量时，`account-password-recovery` 服务配置检查通过。
- [x] 未提供有效恢复输入而实际运行脚本时，脚本仍会中止。

## 测试

已使用本地生产环境文件执行普通部署和启用 `tools` profile 的 Compose `config --quiet`，两项均通过；另以空恢复输入直接运行脚本，脚本在数据库连接前按预期拒绝执行。`git diff --check` 通过。

## 风险 / 回滚

风险限于 Compose 配置解析。脚本仍使用 Zod 校验输入，因此空值不会触发数据库写入。回滚时恢复原插值表达式即可，但会重新引入普通部署阻塞。
