# M6.0 整站视觉与交互重构

## 背景

现有页面已经具备完整的认证、诗作发布、通知和管理流程，但视觉语言在公共内容、成员工作区和管理工作区之间缺少清晰分层，账户与诗作编辑页面也未充分利用桌面空间。本任务以现有首页效果图和桌面创作区参考图为视觉依据，在不改变业务契约的前提下统一整站排版、响应式结构与浮层交互。

## 范围

- [x] 统一暖纸、墨色、低饱和蓝和印章红 Token，建立公共阅读、成员工作区和管理工作区骨架。
- [x] 使用指定诗集实拍照片重构首页，完成桌面竖向、移动端横向锯齿分割和编辑式内容索引。
- [x] 重构诗作列表、详情、长文与认证页面的信息层级和桌面布局。
- [x] 重构账户、账户安全、我的诗作、新建和编辑页面的桌面工作区布局。
- [x] 统一 Popover、DropdownMenu、通知列表和账户菜单的视觉、动效、键盘与焦点行为。
- [x] 统一管理后台导航、筛选、列表、状态和分页的高密度布局。
- [ ] 更新 E2E、视觉截图和 `design-qa.md`，完成质量命令验证。

## 非目标

- [x] 不修改数据库 Schema、migration、认证协议、公开路由或服务端业务行为。
- [x] 不增加自动保存、搜索、评论、点赞、资料编辑或会话管理功能。
- [x] 不创建发布标签，不提前修改版本号。
- [x] 不在首页指定照片之外增加生成式场景图片、假诗作或装饰插画。

## 架构边界

`src/app` 仅负责页面组合；共享页面骨架放在 `src/components/layout`，纯视觉组件放在 `src/components`，业务交互继续留在现有 feature 模块。默认保持 Server Components，只有表单、菜单和通知实时交互保留 Client Components。`PoemFormAction`、`PoemActionState`、字段名称、幂等创建令牌、通知 DTO、管理服务接口和所有安全检查保持不变。Popover 与 DropdownMenu 继续使用 shadcn/ui 和 Radix 上游结构。

## 验收条件

- [x] 首页在 1024px 以上为左文右图，使用 `poetry-collection.jpg`，无渐变遮罩；小屏为单列并切换锯齿方向。
- [x] 账户工作区在桌面端显示约 224px 常驻导航，我的诗作为行式管理列表，编辑器为约 `2fr / 0.8fr` 双栏。
- [x] 小于 1024px 时账户、诗作编辑和管理页面恢复单列或横向二级导航，无水平溢出。
- [x] “我的”菜单包含我的诗作、账户信息、账户安全和独立危险语义登出；通知浮层宽度、滚动区、未读状态和底部入口符合计划。
- [ ] Popover 和 DropdownMenu 支持鼠标、键盘、外部点击、Escape、焦点归还、碰撞定位和 reduced-motion。
- [ ] 公共阅读页、通知中心和主要管理页使用统一视觉语言，现有业务与权限行为无回归。
- [x] `design-qa.md` 的最终结果为 `passed`，任务状态才可更新为已完成。

## 发布影响

- 预期版本影响：`MINOR`
- migration / 环境变量 / 部署顺序：无 migration、无新增环境变量、无特殊部署顺序。
- 兼容性与回滚边界：不改变接口和数据结构；可按视觉基础、公共页面、成员工作区、浮层通知、管理后台阶段逐步回滚。

## 测试

更新首页、账户导航、诗作管理与编辑、账户菜单、通知 Popover 和管理页面相关 E2E；在 390、768、1024、1440px 检查主要页面；验证 reduced-motion、键盘导航、焦点归还和长内容滚动。最终运行 `pnpm check:conventions`、`pnpm typecheck`、`pnpm lint`、`pnpm test`、相关 `pnpm test:e2e` 和 `pnpm build`。

当前已通过约定检查、类型检查、Lint、208 个单元测试、15 个首页相关 E2E 和生产构建。账户、诗作与通知交互 E2E 在复用现有 3000 端口开发服务器时被 HMR WebSocket 握手错误阻断，Client Component 未完成 hydration；按要求没有启动、重启或终止开发服务器，因此任务继续保持“进行中”。

## 风险 / 回滚

主要风险是响应式重排造成操作被遮挡、表单嵌套、浮层焦点回归和首页首屏布局偏移。通过共享骨架、保持原有表单边界、逐视口截图和业务回归测试控制风险。各阶段只包含视觉和组合层变更，可独立回滚。
