# BUG-11 管理导航密度与入口卡片样式

## 背景

视觉复核发现，桌面二级导航相对站点刊头过高、字号过大；管理后台首页的入口条目连续堆叠并带边框，视觉过于拥挤。用户要求缩小导航，并在不修改通用 Card 实现的前提下，为管理场景提供边框更轻、层级更多的卡片样式。

## 范围

- [x] 缩小桌面二级导航字号、纵向内边距、项目间距与活动短线偏移。
- [x] 新增管理后台专用入口卡片组件，复用通用 Card 结构但不修改其实现。
- [x] 为管理入口卡片提供 paper、muted、plain 三种无边框样式，并按业务层级使用。
- [x] 将管理后台首页入口从连续 Item 列表改为有间距的响应式卡片网格。
- [x] 更新设计系统、任务状态和相关单元测试。

## 非目标

- [x] 不修改通用 Card、Item、Surface 的变体或默认样式。
- [x] 不改变管理入口文案、URL、权限与服务端数据逻辑。
- [x] 不改变小于 1024px 的导航信息架构。
- [x] 不运行用户未授权的 Playwright 或其他浏览器自动化。

## 架构边界

桌面导航密度继续由共享 `SecondaryNavigation` 控制；管理入口卡片属于 `src/features/moderation/components`，只组合现有 Card 家族和语义 Token。`src/app/admin/page.tsx` 只负责页面组合与卡片样式选择。

## 验收条件

- [x] 桌面二级导航高度明显降低，文字层级不再压过页面标题。
- [x] 管理入口卡片之间存在稳定间距，所有卡片均无显式边框。
- [x] 三种卡片样式只使用现有 paper、surface muted 与 transparent 层级，不引入随机颜色。
- [x] 通用 Card 的源码和单元快照不因本任务发生变化。
- [x] `pnpm typecheck`、`pnpm lint` 与 `pnpm test` 通过。

## 发布影响

- 预期版本影响：`PATCH`
- migration / 环境变量 / 部署顺序：无。
- 兼容性与回滚边界：可独立恢复管理首页入口列表与导航密度值。

## 测试

新增管理入口卡片三种样式的静态渲染测试，并完成 typecheck、lint、全量单元测试和发布前浏览器回归。

## 风险 / 回滚

主要风险是卡片整块点击区域影响键盘焦点，或两列布局造成较长描述换行。通过真实 Link 语义、`:focus-visible` 父卡片反馈和单列响应式回退控制风险。
