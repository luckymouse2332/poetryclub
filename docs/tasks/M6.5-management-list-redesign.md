# M6.5 管理列表样式改版

## 背景

成员特辑和诗作列表把多个操作并排展示，操作列会撑高整行。管理员列表也需要统一操作密度与信息层级。本任务延续 M6 的工作区视觉语言。

## 范围

- [x] 成员诗作、特辑列表改为紧凑索引行和“主按钮 + 更多”操作区。
- [x] 管理员列表保留详细卡片，统一操作区与元信息间距；一项或两项操作直接显示。
- [x] 特辑收录清单保留排序控件，将移除收入菜单。
- [x] 更新设计规范与受影响的 E2E 验证。

## 非目标

- [x] 不改变详情页操作区、服务端业务规则、数据库或对外 API。
- [x] 不把长内容管理员卡片改为表格或折叠摘要。

## 架构边界

页面保持 Server Component，菜单与动作状态留在对应 feature 的 Client Component。复用现有 shadcn Dropdown Menu、Button、AlertDialog 和项目 IconButton。写入口继续独立校验身份、对象权限、输入和状态；不信任菜单可见性作为授权。列表继续分页。

## 验收条件

- [x] 桌面端成员列表不因多项操作把记录撑为多行按钮；窄屏没有横向滚动。
- [x] 状态对应的菜单项准确；禁用账号没有写操作；隐藏内容没有公开查看入口。
- [x] 删除仍需确认；治理操作仍需原因与确认；错误和提交中状态可感知。
- [x] 菜单、弹窗和排序控件可用键盘操作，关闭后焦点回到合理位置。

## 发布影响

- 预期版本影响：`PATCH`
- migration / 环境变量 / 部署顺序：无。
- 兼容性与回滚边界：仅呈现层变化，可回滚组件改动。

## 测试

`pnpm check:conventions`、`pnpm typecheck`、`pnpm lint`、`pnpm test` 均通过（243 个单元测试）。相关 Playwright E2E 共 24 个场景通过；成员列表覆盖 390、768、920、1024、1440px 视口。按双按钮卡片反馈调整后，用户管理和公告草稿的两条针对性 E2E 再次通过。首次启动 Docker 时数据库短暂重启，清理开发缓存后完整重跑特辑用例通过。

## 风险 / 回滚

菜单转接 Server Action 和弹窗可能影响焦点与错误反馈；通过交互 E2E 与键盘检查验证，必要时回滚菜单组件。
