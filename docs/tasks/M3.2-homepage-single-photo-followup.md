# M3.2 首页单张诗集合照调整

## 背景

M3.1 首页重构使用两张独立照片组成档案拼贴。用户随后提供 `D:\OneDrive\桌面\海报\修改图.jpg`，要求以这张已经同时拍到《杂诗集》封面和展开诗稿的真实合照替换双图，并让首屏更接近原桌面效果图的大幅照片构图。

## 范围

- [x] 将新照片复制到项目资源目录并通过 `next/image` 使用。
- [x] 将首页双照片拼贴改为单张完整合照。
- [x] 调整桌面端和移动端照片比例、裁切与首屏节奏。
- [x] 更新相关首页测试与视觉验收记录。

## 非目标

- [x] 不修改最新诗作查询、认证流程、权限规则或数据库。
- [x] 不删除原始实拍资源，不修改 `master`、`rc1` 或发布流程。

## 架构边界

首页保持 Server Component，只替换静态图片导入、展示结构和局部 CSS。照片使用仓库内静态资源及 `next/image`，不新增依赖、Client Component 或图片生成流程。

## 验收条件

- [x] 首屏只展示一张诗集合照，并准确描述照片内容。
- [x] 桌面端照片成为右侧主要视觉，比例和占位接近原参考效果图。
- [x] 移动端照片位于简介之后，完整可读且无横向滚动。
- [x] lint、typecheck、首页 Playwright 与生产构建通过。

## 测试

更新首页 Playwright 对图片数量、alt 文本和响应式布局的断言；在 375、768、1024、1440 像素视口重新截图，并运行 `pnpm lint`、`pnpm typecheck`、首页 Playwright 和 `pnpm build`。

## 风险 / 回滚

主要风险是宽幅原图在桌面大容器中裁掉书本边缘，或在窄屏下因固定高度造成横向溢出。回滚时恢复 M3.1 的双图结构和对应 CSS 即可，不涉及数据变更。
