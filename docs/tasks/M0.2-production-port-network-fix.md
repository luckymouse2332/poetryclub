# M0.2：生产环境端口发布网络修复

## 背景

生产 Compose 将应用、migration 和 PostgreSQL 全部放在唯一的 `internal: true` 网络中。Docker 接受 `127.0.0.1:4000:3000` 配置，但应用仅连接内部网络时不会建立实际的宿主机端口发布，导致宿主机 Caddy 无法访问 `127.0.0.1:4000`。

## 范围

- [x] 保留 PostgreSQL 与 migration 使用的内部后端网络。
- [x] 为应用增加可发布回环端口的独立入口网络。
- [x] 同步生产部署说明与架构边界。
- [x] 验证 Compose 渲染结果和 Docker 实际端口发布行为。

## 非目标

- [x] 不改变 PostgreSQL 数据卷、Schema 或 migration。
- [x] 不修改宿主机 Caddy 配置或公开监听地址。
- [x] 不把 PostgreSQL 端口发布到宿主机或公网。

## 架构边界

PostgreSQL、migration 与应用之间的数据库通信继续使用 `backend` 内部网络。只有应用连接额外的 `ingress` 网络，宿主机端口仍严格绑定 `127.0.0.1:4000`，数据库不连接入口网络且不声明端口发布。

## 验收条件

- [x] `backend` 继续声明 `internal: true`。
- [x] `db` 与 `migrate` 只连接 `backend`。
- [x] `app` 同时连接 `backend` 与非内部的 `ingress`。
- [x] 应用端口仍配置为 `127.0.0.1:4000:3000`。
- [x] 隔离验证中 Docker 运行时建立宿主机回环端口对容器 `3000` 的端口发布。

## 测试

使用生产环境示例变量执行 `docker compose config`，确认 `db`、`migrate` 只连接内部 `backend`，`app` 同时连接 `backend` 与 `ingress`，发布端口仍为 `127.0.0.1:4000:3000`。使用同等双网络拓扑启动临时容器后，Docker 显示 `127.0.0.1:44000->3000/tcp`，运行时端口绑定存在，宿主机 HTTP 请求成功。`pnpm typecheck`、`pnpm lint` 和 187 项单元测试均通过。

## 风险 / 回滚

应用增加一个普通 bridge 网络后可以通过该网络访问外部地址，但只有回环地址 `127.0.0.1:4000` 被发布，数据库仍隔离在内部网络。回滚可删除 `ingress` 网络及应用对它的连接，但会再次使宿主机端口发布失效。
